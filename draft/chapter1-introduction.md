# 第一章 緒論

## 1.1 研究背景

軟體定義網路（Software-Defined Networking, SDN）將控制邏輯從交換機中抽離，集中到控制器上統一管理。這個架構讓網路管理從逐台設定變成程式化控制，但也創造了新的攻擊面：控制器本身就是高價值目標，而交換機的 flow table 容量有限，兩者都容易被攻擊者利用。

傳統的入侵檢測系統（IDS）依賴已知攻擊特徵進行比對。問題在於攻擊手法會變——攻擊者稍微修改封包模式，特徵庫就跟不上。機器學習方法不需要事先定義規則，但需要大量標記資料訓練，且模型決策缺乏可解釋性，管理者難以理解為什麼某個流量被標記為攻擊。

基於熵值（entropy）的檢測方法走第三條路。它的邏輯很簡單：正常網路的流量分佈是穩定的，受到攻擊時分佈會被打亂——而熵值正好能量化這種「亂度」的變化。不需要知道攻擊長什麼樣子，只要看熵值有沒有異常跳動。

Lakhina 等人最早在 SIGCOMM 2005 證明，透過分析流量特徵的熵值時間序列可以檢測多種網路異常。此後二十年，陸續有研究將熵值應用於不同場景，包括 SDN 環境中的 DDoS 檢測。

但這些方法幾乎都只監測單一維度的熵值。

## 1.2 問題陳述

單一維度熵值面臨三個根本限制。

**第一，無法區分攻擊與正常突發流量。** 當來源 IP 的熵值突然升高，可能是 DDoS 攻擊（攻擊者偽造了大量不同的來源 IP），也可能是 Flash Crowd——正常的爆紅事件導致大量真實使用者同時湧入。只看來源 IP 熵值，兩者長得一模一樣。

**第二，攻擊類型無法辨識。** 即使確定有攻擊，管理者還需要知道「這是哪一種攻擊」才能對症下藥。DDoS 應該啟動流量清洗，Port Scan 只需要封鎖來源 IP，兩種回應策略完全不同。單一維度熵值只會告訴你「有異常」，不會告訴你「是什麼異常」。

**第三，現有方法的熵值估計精度在高流量攻擊情境下會顯著惡化。** 以 Elastic Sketch（Yang et al., SIGCOMM 2018）為例，其內建的熵值估計仰賴 Count-Min Sketch 的計數器分佈，而 CM Sketch 的系統性高估偏差在 elephant flow 密集出現時會扭曲分佈，導致熵值失準。

## 1.3 研究動機與目標

本研究嘗試回答一個問題：如果同時觀察多個維度的熵值變化，能不能既檢測攻擊、又分辨攻擊類型？

背後的直覺是：不同攻擊會在不同流量維度上留下不同的「足跡」。DDoS（偽造來源 IP）會讓來源 IP 熵值飆升，但目的地 IP 熵值大致正常——因為所有攻擊封包都打向同一個受害者。Port Scan 則相反：來源 IP 集中（攻擊者只有一兩台機器），目的地 IP 和埠號卻極度分散。

如果每個時間窗口都記錄六個維度的熵值——來源 IP、目的地 IP、來源埠、目的地埠、流量大小、通訊協定——就可以形成一個六維的「熵值向量」。正常流量有自己的向量範圍，每種攻擊也有各自的偏移模式。比對這些模式，就是本研究的方法核心。

具體目標有三項：

1. **設計多維度熵值計算框架**：基於 Elastic Sketch 的單次遍歷多任務特性，在單一資料結構上同時追蹤六個維度的計數器分佈並計算熵值。
2. **建立攻擊分類規則**：分析各類攻擊在六維熵值空間中的預期偏移方向，設計可解釋的分類邏輯。
3. **實驗驗證**：在 Mininet 模擬的 SDN 環境中，使用真實背景流量混合攻擊流量，與單一維度方法和現有 sketch-based 方法進行比較。

## 1.4 研究貢獻

本研究的貢獻在於：

1. **多維度熵值分析框架**：利用 Elastic Sketch 的架構特性，以不增加額外記憶體和計算開銷的方式同時追蹤六個流量維度的熵值。

2. **基於熵值向量的攻擊分類**：系統性地分析 DDoS（偽造來源 IP）、DDoS（殭屍網路）、Port Scan 及 Flash Crowd 在六維熵值空間中的預期偏移模式，建立可解釋的分類規則——管理者可以清楚看到「為什麼這個流量被判定為 Port Scan 而不是 DDoS」。

3. **CM Sketch 偏差修正**：針對 Count-Min Sketch 在高流量攻擊情境下的系統性高估問題，採用計數器折減策略提升熵值估計精度。

4. **全面的實驗比較**：在相同條件下與 Elastic Sketch 原生熵值方法及 PINT-style 取樣方法進行比較，涵蓋檢測率、分類準確率和資源消耗。

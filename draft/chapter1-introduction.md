# 第一章 緒論

## 1.1 研究背景

軟體定義網路（Software-Defined Networking, SDN）透過控制層與資料層的分離，為網路管理帶來了前所未有的靈活性。傳統網路中，每台交換機各自為政，控制邏輯深嵌在硬體中，任何改動都像要同時改裝整條馬路上的所有紅綠燈。SDN 則把決策權集中到一個「大腦」——控制器，交換機變成聽命的「手腳」，只負責根據控制器下達的規則轉送封包。

這種集中控制的架構在帶來便利的同時，也打開了新的攻擊面。攻擊者不再需要癱瘓整條網路，只要干擾控制器與交換機之間的通訊，或是偽造大量新流量逼迫控制器不斷安裝新規則，就能造成網路癱瘓。更棘手的是，SDN 環境中的攻擊流量往往偽裝成正常流量，傳統的特徵比對（signature-based）方法難以應對。

近年來，基於熵值（entropy）的異常檢測方法逐漸受到重視。熵值衡量的是流量中「亂度」的變化——正常流量有固定的通訊模式，熵值相對穩定；遭受攻擊時，流量分佈會產生劇烈變化，熵值也會隨之跳動。這個方法不需要事先知道攻擊長什麼樣子，因此在面對未知攻擊時具有先天優勢。

## 1.2 問題陳述

然而，現有的熵值檢測方法存在三個根本問題：

**問題一：單一維度的盲點。** 大多數方法只計算一種熵值（例如來源 IP 的熵），並根據閾值判斷是否遭受攻擊。這就像只靠溫度計判斷是否失火——確實，火災時溫度會上升，但暖氣開太大也會。單一維度的熵值無法區分 DDoS 攻擊和 Flash Crowd（瞬間爆紅的正常流量），兩者都會造成流量暴增，但前者是攻擊、後者不是。

**問題二：估計精度與資源消耗的權衡。** 要在高速網路中精確計算熵值，需要追蹤每個 flow 的狀態，這在每秒數百萬封包的 SDN 環境中不可行。Sketch 資料結構（如 Elastic Sketch）提供了輕量級的近似方案，但其熵值估計存在系統性偏差，尤其在攻擊情境下，計數器溢位（counter overflow）和過度估計（over-estimation）會導致誤判。

**問題三：缺乏攻擊分類能力。** 現有方法通常只回答「有沒有攻擊」，而不回答「是什麼攻擊」。DDoS、Port Scan、Low-rate Attack 的流量特徵截然不同，對應的防禦策略也不同。能分辨攻擊類型，才能對症下藥。

## 1.3 研究動機與目標

本研究嘗試回答一個核心問題：**能否透過同時觀察多個維度的熵值變化，來更精確地檢測並分類 SDN 網路中的攻擊？**

核心洞察是：不同類型的攻擊會在不同維度上留下「指紋」。DDoS 攻擊（偽造來源 IP）會導致來源 IP 熵值飆升，但目的地 IP 熵值維持正常；Port Scan 則相反，目的地 IP 和埠號的熵值會大幅上升，但來源 IP 變化不大。透過同時監測六個維度（來源 IP、目的地 IP、來源埠、目的地埠、流量大小、通訊協定），可以為每種攻擊建立獨特的「熵值指紋」，實現檢測與分類的雙重目標。

具體而言，本研究旨在達成以下目標：

1. **設計多維度熵值計算框架**：基於 Elastic Sketch 的單次遍歷多任務特性，在單一資料結構上同時計算六個維度的熵值，避免重複掃描流量。
2. **建立攻擊分類邏輯**：基於各類攻擊的熵值指紋特徵，設計決策規則或輕量級分類器，實現攻擊類型辨識。
3. **實驗驗證**：在 Mininet 模擬的 SDN 環境中，使用真實流量 trace（CAIDA）混合攻擊流量，與現有方法進行全面比較。

## 1.4 研究貢獻

本研究的主要貢獻如下：

1. **提出多維度熵值分析框架**：有別於傳統的單一維度熵值方法，本研究利用 Elastic Sketch 同時追蹤六個流量維度的熵值，形成熵值向量，為攻擊檢測提供更豐富的資訊。

2. **設計攻擊分類矩陣**：系統性地分析 DDoS（偽造來源）、DDoS（殭屍網路）、Port Scan、Flash Crowd 等四種情境下的熵值指紋差異，建立可解釋的分類規則。

3. **高效實作**：所有熵值計算共用單一 Elastic Sketch 資料結構，不增加額外的記憶體和計算開銷，適合部署於資源受限的 SDN 交換機。

4. **全面的實驗評估**：在多種攻擊強度和流量模式下進行實驗，與 Elastic Sketch 原生熵值方法、PINT 方法進行比較，涵蓋檢測準確率、分類精度、延遲和資源消耗等多個維度。

- **第五章 結論**：總結研究成果、討論限制與未來方向

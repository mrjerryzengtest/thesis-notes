# 第二章 文獻探討

本章從三個面向回顧相關文獻：SDN 架構與其安全威脅、Sketch 資料結構的演進、以及熵值在網路異常檢測中的應用。

## 2.1 SDN 架構與安全威脅

### 2.1.1 SDN 基本架構

SDN 的核心概念是控制平面與資料平面的分離。控制器（如 ONOS、Ryu）透過南向介面（以 OpenFlow 為主流）向交換機下達轉送規則。交換機不再自行決定路徑，只根據已安裝的 flow entry 進行封包匹配與轉送。當封包無法匹配任何既有規則時，交換機透過 Packet-In 訊息將封包（或其 header）送交控制器處理。

這個架構的兩個關鍵約束直接影響本研究：第一，交換機的 flow table 使用 TCAM 儲存，容量有限（通常數千到數萬條），攻擊者可以故意製造大量未匹配 flow 來耗盡它。第二，Packet-In 是控制器的效能瓶頸——每秒處理的 Packet-In 數量直接決定控制器能承受的流量上限。

### 2.1.2 針對 SDN 的攻擊

Kreutz et al.（2015）在 IEEE S&P 中系統性地分析了 SDN 的七大攻擊向量。以下三類與本研究直接相關：

**Flow Table 溢位攻擊**：攻擊者高速產生大量短命 flow，迫使交換機不斷安裝新規則直到 TCAM 耗盡，合法流量因無法匹配而被丟棄。這類攻擊的特徵是 flow 數量暴增，但每個 flow 的封包數極少。

**控制層飽和攻擊**：攻擊者針對控制器本身的弱點——發送大量無法匹配的封包，產生密集的 Packet-In 請求，耗盡控制器的 CPU 和頻寬。與 flow table 溢位不同，這類攻擊的特徵是 Packet-In 速率異常高，且來源集中在少數交換機與攻擊主機。

**拓撲毒化攻擊**：攻擊者偽造 LLDP 封包，欺騙控制器建立錯誤的網路拓撲。流量層面上主要表現為特定協定（LLDP）的異常使用模式。

這些攻擊的共同點是：它們改變了某個流量統計維度的分佈模式。flow table 溢位改變 flow 大小分佈，控制層飽和改變來源集中度，拓撲毒化改變協定分佈。這為多維度熵值分析提供了理論基礎——不同攻擊應該在不同的熵值維度上產生可區分的信號。

## 2.2 現有檢測方法的優劣

### 2.2.1 基於規則的方法

傳統 IDS（如 Snort）維護一個龐大的攻擊特徵庫，將流量與已知攻擊模式進行比對。優點是誤報率低——只要特徵寫得夠精確，匹配上的幾乎一定是攻擊。缺點也很明顯：只能檢測已知攻擊，且逐封包比對的成本在高流量環境中難以承受。在 SDN 場景中，部分研究嘗試將 Snort 整合進控制器，透過 OpenFlow 規則將可疑流量鏡像到檢測模組（Xing et al., 2013），但效能瓶頸仍然存在。

### 2.2.2 基於機器學習的方法

ML 方法從流量統計中自動學習正常與異常的邊界。常見做法是擷取 flow-level 特徵（封包數、位元組數、flow 持續時間、埠號分佈等），訓練分類器（SVM、Random Forest、DNN）來區分攻擊與正常流量。Tang et al.（2016）使用深度神經網路在 SDN 環境中檢測 DDoS，Niyaz et al.（2016）使用 stacked autoencoder 進行特徵學習。

ML 方法的主要挑戰在於資料：需要大量標記的攻擊流量進行訓練，而真實 SDN 環境中這類資料難以取得。多數研究使用模擬攻擊資料訓練，模型的泛化能力存疑。此外，深度模型的決策過程不透明——當系統標記某個流量為攻擊，管理者無法確認判斷依據，這在需要即時回應的資安場景中是一個實務障礙。

### 2.2.3 基於熵值的方法

熵值的概念來自資訊理論（Shannon, 1948），衡量隨機變數的不確定性。在流量分析中，熵值量化了某個流量特徵的分佈均勻程度：若所有封包都來自同一個來源 IP，來源 IP 的熵值為 0（完全確定）；若封包均勻分散在大量不同來源 IP，熵值趨近最大值。

熵值方法的優勢是「不依賴攻擊樣本」——任何改變流量分佈的事件都會反映在熵值變化上。缺點是單一維度的熵值只能告訴你「分佈變了」，無法告訴你「為什麼變」以及「變成什麼」。本研究的核心假設是：透過同時監測多個維度的熵值，可以克服這個限制。

## 2.3 Sketch 資料結構的演進

Sketch 是機率式摘要結構，以可控的誤差換取極低的記憶體和計算成本。在網路量測領域，Sketch 被用於估計 flow 大小分佈、檢測 heavy hitter、計算分位數等需要掃描大量封包的任務。

### 2.3.1 Count-Min Sketch

Count-Min Sketch（Cormode & Muthukrishnan, 2005）是最基礎的 Sketch 結構。它使用一個 $d \times w$ 的二維計數器陣列，每個封包經過 $d$ 個獨立的 hash 函數對應到不同列的某個計數器位置，進行遞增。查詢某個 flow 的估計大小時，取對應的 $d$ 個計數器中的最小值。

CM Sketch 的關鍵性質是**只會高估，不會低估**。這項單邊誤差保證使得 CM Sketch 在頻率估計任務中表現優異，但在熵值計算中成為一個障礙：系統性的高估偏差會讓計數器分佈向高計數值偏移，導致熵值被低估（分佈看起來比實際更集中）。

### 2.3.2 Elastic Sketch

Elastic Sketch（Yang et al., SIGCOMM 2018）在 CM Sketch 的基礎上引入了一個關鍵改進：將流量分為 heavy part 和 light part 兩層處理。

Heavy part 使用 hash table 精確追蹤少數大象流（elephant flow），記錄完整的 flow key 和精確計數值。Light part 使用 CM Sketch 壓縮儲存大量老鼠流（mouse flow），只保留計數器分佈的統計摘要。

這個兩層結構有兩個重要特性。第一，自適應 λ 閾值：heavy-light 的分界線不是固定的，而是根據當前流量狀況動態調整，在攻擊情境下能自動適應流量模式的變化。第二，多任務支援：同一份資料結構可以同時回答多種查詢——流量大小估計、heavy hitter 檢測、heavy change 檢測、以及熵值估計。這是本研究選擇 Elastic Sketch 作為底層結構的關鍵原因：我們可以從同一個 Sketch 中同時提取六個不同維度的計數器分佈，而不需要維護六個獨立的資料結構。

Elastic Sketch 原論文提出的熵值估計公式為：

$$H = -\sum_{i=1}^{m} \frac{i \cdot n_i}{N} \cdot \log\left(\frac{n_i}{N}\right)$$

其中 $n_i$ 是計數值為 $i$ 的計數器數量，$N$ 是總封包數。這個公式的精度受制於 CM Sketch 的高估偏差——當大量 elephant flow 存在時，light part 的計數器會被系統性推高。

### 2.3.3 PINT

PINT（Ben Basat et al., SIGCOMM 2020）走了一條不同的路：它不是用 Sketch 來摘要流量，而是讓每個封包攜帶一個「壓縮過的」遙測值（如排隊延遲的編碼），在端點收集後進行統計推斷。PINT 在極低的頻寬 overhead 下實現了多種網路量測任務。

PINT 對本研究最重要的貢獻不是它的方法，而是它的一個負面結論：作者明確指出熵值在低取樣率的條件下難以精確估計（"entropy is poorly approximable from subsampled streams"）。這形成了一個有趣的對比——PINT 說取樣會損害熵值估計，而 Elastic Sketch 的全流量處理可以避免這個問題。本研究的設計延續了這個思路：使用 Elastic Sketch 進行全流量掃描，同時在六個維度上計算熵值，不依賴取樣。

## 2.4 熵值在網路異常檢測中的應用

Lakhina et al.（SIGCOMM 2005）將來源 IP 和目的地 IP 的熵值時間序列輸入 PCA，成功檢測了多種網路異常。這是第一篇系統性證明「熵值可作為網路異常信號」的論文，影響了此後十多年的研究方向。

Nychis et al.（IMC 2008）做了一項重要的實證研究：他們逐一測試了不同流量特徵（IP 位址、埠號、flow 大小）的熵值在檢測各類異常時的表現。結論是：沒有任何單一特徵的熵值能涵蓋所有異常類型。這為多維度方法提供了最直接的經驗證據——既然一個維度不夠，那就應該同時看好幾個。

在 SDN 場景中，Mousavi & St-Hilaire（2015）在控制器上計算目的地 IP 的熵值來檢測 DDoS，原理是 DDoS 集中攻擊少數目標，所以目的地 IP 熵值會異常低。Giotis et al.（2014）結合 sFlow 取樣和 flow 統計特徵進行聯合判斷。Wang et al.（2019）開始嘗試使用三個維度（來源 IP、目的地 IP、埠號）的熵值進行聯合檢測，但缺乏系統性的攻擊分類方法。

從 Lakhina 到 Wang，一個清晰的趨勢是：維度越多，資訊越豐富，檢測越準確。但現有研究尚未解決兩個問題：如何在單一資料結構上高效計算多維度熵值（不增加資源開銷），以及如何建立系統性的攻擊分類邏輯（不只檢測、還能分類）。這兩點構成了本研究的切入點。

## 2.5 本章總結

回顧三個領域的文獻後，本研究的定位逐漸清晰。SDN 的集中控制架構放大了攻擊的影響，但同時也為集中式監測提供了天然的部署點。Elastic Sketch 的兩層結構和單結構多任務特性，為多維度熵值的同時計算提供了高效的底層支援。而從 Lakhina 到 Nychis 的實證研究反覆印證了同一個結論：要準確判斷攻擊，不能只看一個維度。

本研究的設計延續了這條思路，在第三章中提出一個基於 Elastic Sketch 的多維度熵值框架，嘗試同時解決檢測和分類兩個問題。

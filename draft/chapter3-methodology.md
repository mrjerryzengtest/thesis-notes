# 第三章 方法論

本章詳細說明本研究所提出的多維度熵值攻擊檢測與分類框架。全章分為四個部分：系統架構總覽、多維度熵值計算方法、熵值向量正規化與融合策略、以及攻擊分類決策邏輯。

---

## 3.1 系統架構總覽

本系統部署於 SDN 控制器之上，由三個核心模組組成：**資料收集層**、**熵值計算引擎**、和**攻擊分類器**。三者之間的資料流如圖 3.1 所示。

```
┌─────────────────────────────────────────────────┐
│                  SDN Controller                  │
│  ┌───────────┐  ┌──────────────┐  ┌──────────┐ │
│  │  Elastic   │  │ Multi-Dim    │  │ Attack    │ │
│  │  Sketch    │→│ Entropy      │→│ Classifier│ │
│  │  (Data     │  │ Calculator   │  │           │ │
│  │   Plane)   │  │              │  │           │ │
│  └───────────┘  └──────────────┘  └──────────┘ │
│                                                  │
│  檢測結果：Normal / DDoS / Port Scan / ...       │
└─────────────────────────────────────────────────┘
         ↑
    ┌─────────┐     ┌─────────┐
    │ Switch 1│ ... │ Switch N│
    └─────────┘     └─────────┘
```

**資料收集層**使用 Elastic Sketch 結構，部署於每台 SDN 交換機上（或在控制器端進行集中式統計）。當封包經過交換機時，Elastic Sketch 同時更新 heavy part 和 light part 的計數器。與傳統方法不同的是，我們不會將 heavy hitter 與 mouse flow 分開處理——我們需要的是整體流量的統計分佈，而非個別 flow 的細節。

**熵值計算引擎**定期（例如每 5 秒）從 Elastic Sketch 的 light part 計數器陣列中提取六個維度的計數器分佈，各自計算熵值，形成一個六維熵值向量。

**攻擊分類器**接收這個六維向量，透過預先定義的決策規則判斷當前網路是否遭受攻擊，以及攻擊的類型。

### 3.1.1 為什麼選擇 Elastic Sketch

本研究選擇 Elastic Sketch 作為底層資料結構，基於以下三點考量：

1. **單次遍歷，多次查詢**：Elastic Sketch 的 light part 使用 CM Sketch，一次封包處理即可更新所有計數器。透過配置不同的 hash 函數組，我們可以從同一個資料結構中提取不同維度的計數器分佈。

2. **記憶體效率**：Elastic Sketch 的記憶體佔用僅取決於計數器陣列大小，與網路中的 flow 數量無關。在 flow 數量爆炸的攻擊情境下，這項特性至關重要。

3. **現有基準可比較**：Elastic Sketch 原論文提供了單一維度熵值估計的 baseline，我們可以直接與之比較來證明多維度方法帶來的增益。

## 3.2 多維度熵值計算

### 3.2.1 六個監測維度

本研究監測以下六個流量特徵維度的熵值：

| 符號 | 維度 | 說明 | 提取方式 |
|------|------|------|---------|
| $H_{srcIP}$ | 來源 IP 熵值 | 衡量發送封包的 IP 位址分佈均勻度 | 對 srcIP 做 hash → CM Sketch |
| $H_{dstIP}$ | 目的地 IP 熵值 | 衡量接收封包的 IP 位址分佈均勻度 | 對 dstIP 做 hash → CM Sketch |
| $H_{srcPort}$ | 來源埠熵值 | 衡量發送埠號的分佈 | 對 srcPort 做 hash → CM Sketch |
| $H_{dstPort}$ | 目的地埠熵值 | 衡量目標埠號的分佈 | 對 dstPort 做 hash → CM Sketch |
| $H_{flowSize}$ | 流量大小熵值 | 衡量各 flow 的封包數量分佈 | 直接使用 CM Sketch 計數器分佈 |
| $H_{proto}$ | 協定熵值 | 衡量 TCP/UDP/ICMP 等協定使用分佈 | 對 protocol 編號做 hash → CM Sketch |

每個維度獨立使用一組 hash 函數和計數器陣列（或共用同一個 CM Sketch 的不同 hash 函數組），確保各維度之間的統計獨立性。

### 3.2.2 熵值計算公式

對於每個維度 $d$，在時間窗口 $t$ 內，我們從對應的 CM Sketch 中提取計數器分佈：令 $n_{d,i}$ 表示維度 $d$ 中計數值為 $i$ 的計數器數量，$N_d = \sum_i i \cdot n_{d,i}$ 為維度 $d$ 的總封包數。

維度 $d$ 的熵值定義為：

$$H_d = -\sum_{i=1}^{m_d} \frac{i \cdot n_{d,i}}{N_d} \cdot \log_2\left(\frac{i \cdot n_{d,i}}{N_d}\right)$$

其中 $m_d$ 為維度 $d$ 的最大計數值。

為了使不同維度的熵值具有可比性，我們將其歸一化到 $[0, 1]$ 範圍：

$$\hat{H}_d = \frac{H_d}{\log_2(N_d)}$$

歸一化後的熵值 $\hat{H}_d = 0$ 表示所有封包集中在單一數值（極度集中），$\hat{H}_d = 1$ 表示所有數值均勻分佈（極度分散）。

### 3.2.3 時間窗口與滑動平均

熵值對瞬時波動敏感，單一時間窗口的熵值可能因隨機抖動產生誤報。為提高穩定性，我們採用指數加權移動平均（EWMA）：

$$H_d^{smooth}(t) = \alpha \cdot H_d(t) + (1-\alpha) \cdot H_d^{smooth}(t-1)$$

其中平滑係數 $\alpha = 0.3$（預設值，對應約 3 個時間窗口的記憶長度）。

### 3.2.4 CM Sketch 偏差修正

如文獻探討所述，CM Sketch 存在系統性的高估偏差。對於熵值計算而言，高估偏差會導致計數器分佈向高計數值方向偏移，使熵值被低估（因為分佈看起來比實際更「集中」）。

我們採用以下修正策略：對於每個計數器，將計數值減去 CM Sketch 的預期誤差估計。根據 CM Sketch 的理論分析，當使用 $d$ 列、每列 $w$ 個計數器時，任意計數器的期望誤差為：

$$\mathbb{E}[error] \leq \frac{N}{w}$$

實際操作中，我們對計數器 $c_j$ 進行折減：

$$c_j^{corrected} = \max(0, c_j - \epsilon)$$

其中 $\epsilon = \frac{N}{w}$ 為誤差閾值，$N$ 為總封包數，$w$ 為 CM Sketch 的列寬。折減後，重新計算總封包數 $N^{corrected} = \sum_j c_j^{corrected}$，再用 $c_j^{corrected}$ 代替原始計數值計算熵值。

## 3.3 熵值向量與攻擊指紋

經過上述計算後，每個時間窗口產出一個六維的歸一化熵值向量：

$$\mathbf{H}(t) = [\hat{H}_{srcIP}, \hat{H}_{dstIP}, \hat{H}_{srcPort}, \hat{H}_{dstPort}, \hat{H}_{flowSize}, \hat{H}_{proto}]$$

### 3.3.1 攻擊指紋概念

不同類型的網路事件會產生不同的熵值向量模式，我們稱之為「熵值指紋」。以下是基於理論分析和實驗觀察建立的指紋矩陣：

| 事件類型 | H_srcIP | H_dstIP | H_dstPort | H_flowSize | H_proto |
|----------|:-------:|:-------:|:---------:|:----------:|:-------:|
| **正常流量** | 中 | 中 | 中 | 中 | 中 |
| **DDoS（偽造來源 IP）** | ↑↑ 高 | → 正常 | → 正常 | ↑ 偏高 | → 正常 |
| **DDoS（殭屍網路）** | ↑ 偏高 | → 正常 | → 正常 | ↑↑ 高 | → 正常 |
| **Port Scan** | → 正常 | ↑↑ 高 | ↑↑ 高 | ↓ 低 | → 正常 |
| **Flash Crowd** | ↓ 低 | ↑↑ 高 | ↑ 偏高 | ↑↑ 高 | → 正常 |
| **控制層飽和攻擊** | ↓↓ 低 | ↓ 偏低 | ↓↓ 低 | ↓↓ 低 | ↓ 異常 |

↑ 代表熵值高於正常水準（分佈更分散），↓ 代表熵值低於正常水準（分佈更集中）

### 3.3.2 各攻擊類型的流量解釋

**DDoS（偽造來源 IP）**：攻擊者隨機偽造來源 IP，使得來源 IP 極度分散 → $H_{srcIP}$ 高。但目的地集中於受害主機 → $H_{dstIP}$ 正常或偏低。每個被偽造的來源只發少量封包 → $H_{flowSize}$ 只略高於正常。

**DDoS（殭屍網路）**：殭屍主機的真實 IP 數量有限 → $H_{srcIP}$ 僅略高。但每個殭屍主機發送大量封包（類似 elephant flow）→ $H_{flowSize}$ 顯著升高。這是區分偽造型 DDoS 和殭屍網路 DDoS 的關鍵。

**Port Scan**：攻擊者從單一或少數 IP 掃描目標的多個埠 → 來源集中、目的地和埠號極度分散。每個掃描 flow 只有極少封包（通常 1-2 個）→ $H_{flowSize}$ 低。

**Flash Crowd**：正常使用者大量湧入 → $H_{srcIP}$ 低或正常（使用者群有限）、$H_{dstIP}$ 高（可能涉及多台伺服器）、$H_{flowSize}$ 高（每個使用者產生實質流量）。關鍵區別：與 DDoS 不同，Flash Crowd 的來源 IP 熵值不會異常高。

**控制層飽和攻擊**：攻擊者發送大量不匹配 flow table 的封包 → 每個 flow 都極短（1 封包）、主要集中在少數攻擊機器 → 所有維度熵值偏低，$H_{proto}$ 可能異常。

## 3.4 攻擊分類決策邏輯

### 3.4.1 基於閾值的兩階段分類

本研究採用兩階段分類策略：

- **第一階段（檢測）**：判斷是否發生異常
- **第二階段（分類）**：識別異常類型

#### 第一階段：異常檢測

使用多維度熵值的 **Euclidean 距離**來判斷異常。首先建立正常流量的基準向量（baseline profile），透過在無攻擊時段採集熵值向量的平均值：

$$\mathbf{H}_{baseline} = \frac{1}{T}\sum_{t=1}^{T} \mathbf{H}(t) \quad \text{（無攻擊時段）}$$

在每個時間窗口，計算當前向量與基準向量的歐氏距離：

$$D(t) = \|\mathbf{H}(t) - \mathbf{H}_{baseline}\|_2$$

當 $D(t) > \tau_{detect}$ 時，觸發異常警報。檢測閾值 $\tau_{detect}$ 根據訓練期間（無攻擊時段）距離分佈的 99 百分位數設定。

#### 第二階段：攻擊分類

觸發異常後，根據各維度熵值相對於基準的變化方向，匹配攻擊指紋。具體步驟：

1. 計算偏移向量 $\Delta\mathbf{H} = \mathbf{H}(t) - \mathbf{H}_{baseline}$
2. 將每個維度量化為三個等級：↑（偏高）、→（正常）、↓（偏低）
3. 與 3.3 節的指紋矩陣進行匹配
4. 採用加權相似度評分，權重根據各維度對特定攻擊的區分能力設定

量化規則：

- 若 $\Delta H_d > \sigma_d$：標記為 ↑（偏高）
- 若 $\Delta H_d < -\sigma_d$：標記為 ↓（偏低）
- 否則：標記為 →（正常）

其中 $\sigma_d$ 為維度 $d$ 在正常流量中的標準差。

### 3.4.2 替代方案：輕量級分類器

除閾值規則外，我們也考慮使用輕量級分類器處理複雜的混合攻擊情境。候選方案包括：

- **決策樹（Decision Tree）**：可解釋性強，規則可直接對應到指紋矩陣
- **KNN（K-Nearest Neighbors, k=3）**：無需訓練，適合流式資料

兩者的輸入都是六維熵值向量，輸出為攻擊類型標籤。

## 3.5 方法總覽流程

```
每個時間窗口 t：
  1. 從 CM Sketch 讀取六個維度的計數器分佈
  2. 執行偏差修正（§3.2.4）
  3. 計算各維度熵值 + 歸一化（§3.2.2）
  4. EWMA 平滑（§3.2.3）
  5. 計算與基準向量的歐氏距離
  6. 若 D(t) > τ_detect：
     a. 計算偏移向量
     b. 匹配攻擊指紋矩陣
     c. 輸出攻擊類型
  7. 否則：輸出 Normal
```

## 3.6 複雜度分析

### 時間複雜度

每個時間窗口的操作複雜度：

| 步驟 | 複雜度 | 說明 |
|------|--------|------|
| 讀取計數器分佈 | $O(d \cdot w)$ | d 列、w 行的 CM Sketch |
| 偏差修正 | $O(d \cdot w)$ | 每個計數器一次減法 |
| 熵值計算 | $O(d \cdot w)$ | 一次遍歷 |
| 分類決策 | $O(1)$ | 固定六維向量比對 |

總時間複雜度：$O(d \cdot w)$，其中 $d \cdot w$ 為 CM Sketch 的總計數器數。在典型配置下（$d=3, w=2^{12}$），約 12K 次操作。

### 空間複雜度

六個維度各使用一個獨立的 CM Sketch，每個 Sketch 記憶體佔用：$d \times w \times 4$ bytes（假設每個計數器 32-bit）。

總記憶體：$6 \times 3 \times 4096 \times 4 \approx 288$ KB。

相較於基於 flow table 的方法（可能需要數十 MB 甚至上百 MB），本方法的記憶體效率極高，適合部署於資源受限的 SDN 交換機。
